## My engineering approach

- Infrastructure as code first, no manual portal changes as the system of record
- Automation over toil, especially for repeatable fleet and release work
- Reliability and observability together, so issues surface before customers are affected
- Security-aware delivery, with secrets in Key Vault and approval gates on production changes
- Small, reviewable, reversible changes, so a bad release is a rollback, not a rebuild
